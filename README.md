# NomadEX

NomadEX помогает бизнесу сформулировать задачу, получить предложения студенческих команд и подтвердить результат работы.

## Текущий этап: P0

В ветке `codex/p0-backend-database-permissions` локальный MVP переведён на backend и общую SQLite. Бизнес и команды регистрируются отдельно; данные, права, рейтинг, решение и баллы проверяются сервером. Переключателя демопрофилей больше нет. Публичное развёртывание ещё не выполнено.

Все восемь шагов MVP сохранены: черновик → AI-вопросы → карточка → рейтинг → каталог → отклик → выбор команды → результат и +10 баллов. Сохраняются 11 полей, 7 критериев рейтинга, фильтры и пять встроенных прототипов. AI не публикует задачи и не выбирает исполнителей.

## Быстрый запуск

Нужны Node.js **24 или новее** и npm. В PowerShell при блокировке `npm.ps1` используйте `npm.cmd`.

```sh
npm ci
npm run dev
```

Откройте [http://127.0.0.1:5173](http://127.0.0.1:5173), зарегистрируйте бизнес или команду. Новая база пуста. Миграции применяются автоматически, файл по умолчанию — `data/development.sqlite`. Черновик нужно явно сохранить перед подтверждением и публикацией. Очистка браузера не удаляет серверные задачи.

Для AI скопируйте `.env.example` в `.env` и задайте `OPENAI_API_KEY` и `OPENAI_MODEL`. Ключ хранится только на сервере, не в `VITE_*`. Без ключа доступны явно обозначенные локальные подсказки. Реальные запросы расходуют лимит OpenAI; `npm test` не обращается к провайдеру.

Для демоданных: на **пустой development-БД** установите собственный временный `SEED_PASSWORD` (12–128 символов) и выполните `npm run db:seed`. Команда напечатает адреса шести демоаккаунтов, но не пароль. Seed не перезаписывает существующую БД и запрещён при `NODE_ENV=production`.

## Проверка двумя пользователями

1. В первом браузере зарегистрируйте бизнес, создайте и сохраните задачу. Проверьте поля, подтвердите и опубликуйте.
2. В другом браузере/приватном окне зарегистрируйте команду. Откройте общий каталог и отправьте отклик. Можно указать встроенный пример `/prototypes/demo.html?example=requests`.
3. Вернитесь к бизнесу, дождитесь обновления (до 5 секунд) или нажмите «Обновить данные». Выберите команду и подтвердите решение.
4. Команда отправляет результат; бизнес подтверждает его. Команда получает +10, повторное подтверждение не добавляет баллов.
5. Перезагрузите оба окна. Данные и действующие сессии сохраняются. Другой бизнес не видит черновики и не может изменить чужую задачу.

Обычные вкладки одного браузера используют общую cookie-сессию. Для независимых аккаунтов нужны разные профили/браузеры или обычное и приватное окно. На разных устройствах откройте один развёрнутый сервер, а не отдельные локальные копии.

## Архитектура и права

| Часть | Реализация |
|---|---|
| Интерфейс | React 18, Vite 6, TypeScript |
| Общие правила | `shared/domain.ts`, Zod, 11 полей и 7 критериев |
| HTTP API | Node.js `node:http`, `server/platform.ts` |
| База | SQLite через `node:sqlite`, внешние ключи, WAL, транзакции, миграции |
| Аккаунты | Пароли scrypt с индивидуальной солью; отзываемые HttpOnly-сессии |
| Права | Сервер определяет роль и владельца по сессии; CSRF и разрешённые Origin |
| Конкурентность | Общая ревизия, конфликт 409; повтор запроса с тем же ID не дублирует действие |
| Аудит | Журнал важных изменений; восстановление состояния в отдельную копию БД |
| AI | Существующий OpenAI Responses API, доступ только вошедшему бизнесу |

Клиент отправляет команды, а не всё состояние: нельзя передать чужую роль, готовый рейтинг, баллы или дату подтверждения. Черновики доступны владельцу, отклики и результаты — владельцу задачи и соответствующей команде. Опубликованные задачи, профили и суммарные баллы команд доступны вошедшим пользователям.

Пароли, cookie-токены и служебные записи не попадают в каталог. Старое `localStorage` не загружается на сервер автоматически; исторические функции миграции сохранены отдельно и покрыты прежними тестами.

## Проверки

```sh
npm run typecheck
npm test
npm run build
```

68 тестов: 56 прежних и 12 новых backend-тестов. Проверяются права, авторизация, CSRF, конфликты, повтор запросов, полный цикл, восстановление БД, аудит, ограничения запросов и безопасная раздача файлов. Браузерный сценарий двух независимых сессий пройден вручную до +10 после перезагрузки. Повторный платный AI-вызов в P0 не выполнялся; прежняя приёмка реального OpenAI зафиксирована отдельно.

Для просмотра сборки: `npm run server` и в другом терминале `npm run preview`. Для одного сервера, HTTPS-пилота и разных устройств используйте [руководство P0](docs/backend-p0.md).

Это основа небольшого пилота, не завершённая production-платформа. Пока нет восстановления пароля, проверки email, модерации, участников внутри одной организации, редактирования опубликованных задач, нескольких этапов, уведомлений и автоматического расписания резервных копий. SQLite рассчитана на один сервер с локальным диском; горизонтальное масштабирование требует отдельной архитектуры. Публичный адрес не развёрнут.
