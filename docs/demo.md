# Демонстрация до пяти минут

План на 4:40, запас 20 секунд. Один пример: «Единый список заявок». Все сведения и адрес связи синтетические. Показать работу приложения, а не слайды. Автоматизированный проход этого примера в браузере занял 103 секунды без устного рассказа; время выступления с объяснениями следует отрепетировать отдельно.

## Подготовка перед защитой

Запустить приложение по README, проверить `npm run check:openai`, открыть бизнес-профиль. Подготовить тексты ниже для вставки. Если нужен чистый набор, сбрасывать только своё демонстрационное состояние: сброс удаляет изменения. Открыть этот документ рядом. Не показывать `.env` или ключ. Сбой сети не скрывать: использовать явно подписанные локальные вопросы и ранее зафиксированный протокол реального запроса.

## Хронометраж

| Время | Действие и проверяемый результат |
|---|---|
| 0:00–0:25 | «Новая задача». Ввести название, тему «Клиентский сервис» и слабое описание: «Заявки теряются между таблицами. Хотим видеть их в одном месте». Предварительный рейтинг 0. |
| 0:25–0:55 | «Найти пробелы и вопросы». Показать режим OpenAI и минимум три уместных вопроса. Ответить на вопрос о контексте и добавить ответ соответствующей кнопкой. Модель не заполнила карточку фактами сама. |
| 0:55–2:00 | Внести подготовленные сведения. Показать рост до 100, семь вкладов рейтинга и уровень «Приоритетная». Подтвердить все заполненные поля. Изменить срок: подтверждение снимается, публикация блокируется. Проверить и подтвердить повторно. |
| 2:00–2:30 | Опубликовать. Новая карточка первая среди задач с 100 баллами. Показать фильтр 0–39: задача с 15 баллами доступна; сбросить фильтр. Показать фильтр по теме, затем сбросить. |
| 2:30–3:15 | Переключиться на DataCraft, открыть новую задачу и отправить подготовленный отклик со ссылкой на встроенный прототип. Открыть ссылку, добавить заявку и изменить статус. Вернуться к платформе. |
| 3:15–3:50 | Переключиться на бизнес, прочитать предложение, отметить DataCraft, «Проверить решение» → «Подтвердить выбор команд». Объяснить: можно выбрать несколько или ни одной команды; AI решения не принимает. |
| 3:50–4:25 | DataCraft отправляет результат. Баллы ещё 0. Бизнес подтверждает результат (+10). Вернуться на DataCraft, перезагрузить: +10 и задача сохранены. |
| 4:25–4:40 | Показать, что рейтинг задачи не изменился от баллов команды. Обозначить границы: один браузер, демопрофили, без общей серверной БД. |

## Подготовленные сведения для карточки

| Поле | Текст |
|---|---|
| Контекст | Менеджеры вручную переносят заявки и пропускают обращения. |
| Потребность | Нужен единый список заявок со статусами. |
| Пользователи | Менеджеры клиентского сервиса. |
| Данные | Две вымышленные заявки во встроенном примере; можно добавлять свои тестовые записи. |
| Ожидаемый результат | Веб-прототип списка заявок. |
| Критерии успеха | Добавить третью заявку, изменить статус и отфильтровать открытые. |
| Границы | Список и статусы; без платежей и CRM. |
| Сроки и ограничения | Неделя; только синтетические данные. Для показа сброса подтверждения изменить неделю на две. |
| Рабочий контакт | demo-business@example.com (вымышленный контакт). |
| Консультации | Онлайн, 20 минут по согласованию. |
| Обратная связь | Замечания после демонстрации в течение двух рабочих дней. |

Промежуточно: только контекст + потребность дают 20; добавление данных даёт 40; заполнение всех полей даёт 100. До ручного подтверждения это предварительная оценка.

- Текст результата: «Подготовлен демонстрационный список заявок со сменой статусов».

Это демонстрационный отклик на вымышленную задачу. Пример по ссылке не считается автоматически принятым результатом.

## Дополнительные проверки вне основного показа

В черновике открыть «Проверка AI для демонстрации»: промпт версии 2, вход, выход и «Проверить неверный ответ». Для каждого варианта (не JSON, два вопроса, неизвестное поле) вывод отклоняется без изменения карточки, включаются локальные вопросы. Сценарии выбора нескольких/ни одной команды, некорректных ссылок и повторного начисления проверяются тестами и описаны в `mvp-verification.md`.
