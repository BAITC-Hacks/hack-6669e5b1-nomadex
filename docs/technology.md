# Технологии пятичасового прототипа

## Решение

Интерактивное веб-приложение на **Vite + React + TypeScript**, обычный CSS и **localStorage**. **Zod** проверяет структуру AI-ответов и сохранённого состояния. Это заменяет первоначальный план с Next.js, Prisma и SQLite: бизнес-данные остаются в браузере, а для обязательной интеграции OpenAI добавляется минимальный Node.js-сервер с одним endpoint.

Прототип демонстрирует все восемь шагов, переключая одного представителя бизнеса и пять команд в одной вкладке. Данные сохраняются в этом браузере для того же адреса приложения. Каталог общий для демопрофилей; общей базы между браузерами и устройствами нет. Это ограничение должно быть указано в интерфейсе демонстрации.

| Компонент | Решение | Почему |
|---|---|---|
| Интерфейс | React + TypeScript | Формы, карточки, таблица предложений и явные состояния |
| Запуск и сборка | Vite, шаблон react-ts | Минимальный каркас приложения |
| Оформление | Обычный CSS | Без настройки дизайн-системы и дополнительных библиотек |
| Состояние | React useReducer и функции бизнес-правил | Одна точка изменения задач, откликов и результатов |
| Хранение | localStorage, один JSON с schemaVersion | Без сервера БД и миграций |
| Валидация | Zod | Проверка AI-выхода и загружаемого состояния |
| AI | OpenAI Responses API + официальный пакет openai | Анализ описания и генерация уточняющих вопросов |
| Сервер AI | Node.js, встроенный HTTP-сервер, POST /api/analyze-task | Ключ остаётся на сервере; валидация входа и выхода |
| Проверки | TypeScript, production-сборка, ручной чек-лист | В пределах последнего часа по roadmap |

[Vite предоставляет шаблон React + TypeScript](https://vite.dev/guide/). [localStorage относится к конкретному origin браузера](https://developer.mozilla.org/en-US/docs/Web/API/Web_Storage_API/Using_the_Web_Storage_API) и подходит здесь именно для локального показа. [Zod safeParse](https://zod.dev/basics) позволяет обработать неверную структуру без падения интерфейса. Выбор стека — проектное решение под лимит времени.

## Установка

Node.js и npm уже установлены по сообщению пользователя. Дополнительная глобальная установка не требуется. React, Vite, TypeScript, Zod и официальный SDK openai устанавливаются локально в проект вместе с package.json и lockfile при начале реализации. Перед созданием проекта проверить совместимость установленной версии Node.js с выбранной версией Vite.

Каркас проекта уже создан. Проверка: `npm ci`, `npm run typecheck`, `npm test`, `npm run build`; запуск — `npm run dev`. README остаётся без изменений. Node.js должен быть доступен в PATH (при установке через nvm сначала активировать его в терминале). Для регрессионных тестов используется встроенный node:test через tsx; отдельные Vitest и Playwright не устанавливаются. Prisma, сервер БД и Docker пока не нужны. Пакет openai обязателен.

## Архитектура

```text
Разделы React: мастер / каталог / отклики / результат
                         ↓
Общие функции: валидация, рейтинг, переходы состояния
                ↓                         ↓
     React state → localStorage    POST /api/analyze-task
                                           ↓
                               Node.js → OpenAI Responses API
                                           ↓
                               Проверка JSON / резерв mock
```

Рейтинг вычисляется из текущих полей, а баллы команды — из подтверждённых результатов. Не хранить независимо изменяемый баланс: один подтверждённый результат даёт +10 при каждом пересчёте, а не при каждом клике.

Минимальные записи в общем состоянии:

- `Task`: id, businessId, title, description, industry, шесть полей карточки (строка или null), questions, answers, readinessScore, scoringVersion, confirmed, status (`draft` / `published`), publishedAt, decisionFinalizedAt.
- `Proposal`: id, taskId, teamId, approach, plan (массив шагов), expectedResult, timing, skills, link, status (`submitted` / `selected` / `rejected`). Не более одного отклика на пару taskId/teamId.
- `Result`: proposalId, text, confirmedAt. Не более одного результата на выбранный отклик. Отсутствие confirmedAt означает, что баллы ещё не начислены.
- Демопрофили бизнеса и команд: фиксированные id; для пяти команд — name, interests, skills и technologies отдельными полями, без персональных или чувствительных признаков.

До публикации редактирование сбрасывает confirmed; после публикации редактирование задачи отключено. Решение бизнеса одним изменением состояния фиксирует выбранные и отклонённые отклики и закрывает приём новых. Нулевой выбор допустим только после явного подтверждения. Результат отправляет выбранная команда, подтверждает бизнес.

Проверки текущего демопрофиля в общей функции изменения состояния обеспечивают корректность сценария через интерфейс. Это не полноценная авторизация: localStorage доступен владельцу браузера для изменения. Параллельная работа нескольких вкладок и разрешение конфликтов не поддерживаются.

## Сохранение и ошибки

Состояние записывается в один ключ localStorage с версией схемы. Seed создаётся только при отсутствии сохранения. Полный контракт загрузки JSON/CSV версии 2 описан в [source-data.md](source-data.md): drafts и tasks объединяются без смены id, results первоначально пуст, существующие опубликованные карточки и отклики повторно не создаются. Для ссылок seed используются локальные разделы демонстрационных предложений; UI открывает их либо показывает соответствующее предложение по id. Ошибка чтения/записи показывается пользователю; при недоступном хранилище можно продолжить в памяти с предупреждением. Повреждённое сохранение не затирается молча: предложить явный сброс демоданных. Явный сброс записывает исходный seed в основной ключ приложения; старые копии черновика и прочие данные браузера сохраняются.

## Обязательная интеграция OpenAI

Использовать официальный JavaScript SDK `openai` и Responses API. Системный промпт передаётся как инструкции, описание и ответы — как пользовательские данные. Запросить Structured Outputs с JSON Schema через `text.format`, затем проверить результат Zod и прикладными правилами. Документация: [OpenAI quickstart](https://developers.openai.com/api/docs/quickstart), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

Серверный `POST /api/analyze-task` принимает вход из [ai-contract.md](ai-contract.md), проверяет его и вызывает OpenAI. Vite проксирует `/api` к локальному серверу; браузер не вызывает OpenAI напрямую. Сервер слушает loopback для локальной демонстрации. Полноценный backend для задач и пользователей не нужен.

Настройки сервера: `OPENAI_API_KEY` и `OPENAI_MODEL`. Модель выбрать из доступных проекту OpenAI с поддержкой Responses API и Structured Outputs и проверить реальным запросом в первые 30 минут. Ключ передавать через окружение процесса; если используется локальный env-файл, исключить его из Git и явно настроить загрузку. В будущем `.env.example` содержит только пустой ключ и имя модели, без секретов. Ключ не помещать в React, localStorage, переменные `VITE_*`, логи и ответы endpoint.

Для ограничения времени настроить таймаут 15 секунд и отключить автоматические повторы SDK (`maxRetries: 0`). При ошибке endpoint возвращает понятный код без секретов, клиент предлагает или показывает локальные резервные вопросы с явной пометкой. Режим по умолчанию — `openai`; `mock` используется для сбоев и отдельной проверки ошибок.

Готовность: минимум один успешный реальный анализ описания с API-ключом, валидными вопросами и режимом `openai`, плюс проверка ошибочного ответа и недоступности API. Mock без успешного OpenAI-вызова означает, что интеграция ещё не проверена. Код адаптера реализован; в текущей проверке живой запрос не выполнялся из-за отсутствия ключа. Тестовые адаптеры проверяют контракт и ошибки, но не подтверждают доступ к OpenAI.

Переход к общей БД, реальным аккаунтам и серверной проверке прав — отдельная задача после прототипа.

## Текущее состояние реализации

Общий store реализован в `src/store.ts`, подключён через useReducer в `src/App.tsx` и сохраняет весь объект с schemaVersion=2 в ключе `nomadex-state-v2`. Начальный seed объединяет пять черновиков и пять опубликованных карточек без смены id, один бизнес, пять команд и пять откликов; results первоначально пуст. Zod проверяет записи, ссылки между ними и соответствие рейтинга полям. При наличии валидного сохранения seed повторно не добавляется.

`src/storage.ts` используется для переноса прежнего рабочего черновика из `nomadex-draft-v2` либо `nomadex-draft-v1`, если основного сохранения ещё нет. Исходная копия остаётся в браузере. Повреждённое сохранение блокирует автоматическую перезапись до явного сброса; при недоступном хранилище интерфейс продолжает работать в памяти и показывает предупреждение.

Бизнес создаёт задачи и видит свой список. `src/DraftEditor.tsx` редактирует выбранный черновик; ответы сохраняются, текущий AI-анализ остаётся состоянием редактора. Изменение сбрасывает подтверждение. Публикация требует заголовка, описания и подтверждения, сохраняет id и фиксирует карточку. `src/TaskView.tsx` показывает её без редактирования. Все команды видят каталог опубликованных карточек с сортировкой по рейтингу, дате и id. Store проверяет владельца и допустимость каждого перехода; команды не могут менять черновики или публиковать их.

Подача откликов, сравнение и решение бизнеса — следующий этап. Исходные отклики уже доступны в состоянии, но действий и интерфейса для них пока нет. Для результатов определена только схема; начисление баллов ещё не реализовано. Проверки: 25 тестов через node:test, проверка типов, production-сборка и ручной прогон публикации/каталога в браузере.

Единый контракт AI находится в shared/contract.ts, промпт — в shared/prompt.ts. API сервер возвращает валидный результат с mode=openai и promptVersion=1 либо ошибку `{code}`. На ошибке клиент строит локальные вопросы с mode=mock и показывает причину. Сервер не сохраняет карточки и не изменяет их поля. Серверный SDK и секреты не импортируются в React. .env исключён из Git; .env.example содержит только образец конфигурации. Vite dev и preview проксируют /api на loopback и учитывают PORT; для preview отдельно запустить `npm run server`.
