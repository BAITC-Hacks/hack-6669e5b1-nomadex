## Автоматические проверки

Из корня проекта при доступном Node.js выполнить:

```sh
npm run check
```

Команда последовательно запускает TypeScript, тесты и production-сборку. Текущий результат: **47 тестов пройдены**, типы и сборка проходят.

Дополнительные семь тестов проверяют официальный OpenAI SDK с подменённым транспортом: формат Responses API, отдельные инструкции и данные пользователя, строгую JSON Schema, `store: false`, контролируемые ошибки 401/403/429/500 без повторов, обработку таймаута и потери связи, отказ модели, неполный/пустой ответ, отклонение неверного JSON-контракта через HTTP endpoint и поведение команды без конфигурации. Конфигурация из одних пробелов теперь отклоняется до вызова SDK.

Эти тесты проверяют программные ветки, а не доступ к OpenAI, качество генерации или реальную длительность таймаута сети. Внешние запросы при `npm run check` не выполняются.

## Как повторить проверку OpenAI

1. Создать локальный `.env` по `.env.example`, если его ещё нет. Заполнить OPENAI_API_KEY и доступную проекту OPENAI_MODEL с поддержкой Responses API и Structured Outputs. `.env` исключён из Git. Не помещать ключ в переменные VITE_*.
2. Выполнить `npm run check:openai`. Команда отправляет один синтетический пример через временный штатный сервер на loopback; отдельный `npm run dev` для неё не нужен. Используется реальный API, поэтому запрос расходует квоту аккаунта.
3. Ожидать код 0, mode=openai и 3–6 валидных вопросов. Код 2 означает отсутствие конфигурации; код 1 — неуспешную проверку. Mock не может выдать положительный результат этой команды.
4. Вручную оценить вопросы: они должны уточнять пробелы, не утверждать неизвестные факты и не запрашивать чувствительные признаки.
5. Запустить или перезапустить `npm run dev`, открыть черновик, нажать «Найти пробелы и вопросы». Проверить надпись «Вопросы подготовлены OpenAI», промпт/вход/выход в панели демонстрации. Поля карточки не должны меняться сами.
6. После фактического успеха записать дату, модель и результат в этом документе и закрыть соответствующий пункт roadmap. Ключ и заголовки авторизации в отчёт не включать.

Текущий статус — «локальный MVP и реальный AI проверены». Следующий этап разработки описан как P0 в [post-mvp-roadmap.md](post-mvp-roadmap.md); backend и общая БД в текущий проход не входили.
