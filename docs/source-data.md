# Исходные данные MVP

Набор демонстрационных данных для пятичасового прототипа. Все записи обезличены и не содержат персональных или чувствительных признаков. Идентификаторы стабильны, чтобы связывать задачи, команды и отклики в `localStorage`.

Отдельные файлы для загрузки:

- [source-data.json](source-data.json) — структурированный формат с коллекциями черновиков, карточек, команд и откликов.
- [source-data.csv](source-data.csv) — плоский нормализованный формат с типом записи в поле `entity_type`.

## Правила загрузки

- При первом запуске создаются все записи из этого документа.
- Черновики не показываются в общем каталоге.
- Карточки с `status: published` показываются в каталоге и сортируются по `readinessScore` по убыванию.
- Поле `readinessScore` является демонстрационным начальным значением; в приложении его нужно пересчитывать функцией рейтинга из [roadmap.md](roadmap.md).
- У каждой команды может быть не более одного отклика на одну задачу.
- Тексты ниже являются исходными данными для интерфейса, а не результатом работы AI.

## Сквозной демонстрационный прогон

1. Открыть черновик `task-draft-001`, получить уточняющие вопросы и перенести ответы в поля карточки.
2. Подтвердить карточку `task-001` и проверить, что рейтинг виден по критериям.
3. Открыть каталог и убедиться, что опубликованные задачи отсортированы по рейтингу: `task-001`, `task-002`, `task-003`, `task-004`, `task-005`.
4. С профилями команд проверить отправку и сравнение `proposal-001` и `proposal-002` для одной задачи.
5. Проверить три варианта решения бизнеса на разных демонстрационных запусках: выбрать одну команду, несколько команд и ни одной команды.
6. Для выбранной команды отправить один результат этапа и подтвердить его от имени бизнеса. Начислить ровно `+10` командных баллов; повторное подтверждение не должно начислять баллы снова.
